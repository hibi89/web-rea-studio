## Scope and distinction

The prior F3/Q1 anonymous geometry HTML was derived only from previously saved failed/interrupted passive evidence and was not a source clone. Its computed grid, horizontal overflow, and mobile stack were proven in isolated Chrome tests but were **not bound to a particular stored run's HTML/evidence snapshot**. This feature explicitly bridges that gap. The only output verified is **an anonymous local synthetic generated HTML preview**, not source-site mobile responsiveness, original JS, true API response schemas, backend/database, appearance, or functional parity.

## New implementation

- `studio/f3-q1-acceptance.mjs`: recompute current saved-run anonymous HTML and SHA-256, plus SHA-256 of the same saved inspection/report/diagnosis. Reject ineligible saved passive capture. For each of the **fixed** offline viewports 1440×900 and 390×844, use `runDynamicAnalysis` with `scriptsDisabled:true`, `observeAnonymousLayout:true`, bounded `offlineViewport`, and exact synthetic in-memory document relay. No original site requested, no click, form, external resources, new host allowance, added credentials or deployment.
- Every viewport must show a successful Chrome report, scripts not executed, fetch attempts and rejections zero, blocked resources zero, expected screenshot bounds, zero native action controls and `assessAnonymousLayout` decision `PASS_GENERATED_OFFLINE_LAYOUT`. The two views produce computed columns **3** and **1** respectively, 9 anonymous zones, horizontal overflow false.
- Only after BOTH pass, write `f3-q1-layout-acceptance.json` to the existing run directory once using private mode 0600 and exclusive `wx`. Receipt uses `VERIFIED_SYNTHETIC_LAYOUT_ONLY`, `html_sha256`, `evidence_sha256`, per-view bounded metrics, and explicit `source_site_refetched:false`, `original_site_parity_verified:false`, `original_mobile_layout_verified:false`, `permission_status:NOT_APPROVED`, `product_ready:false`. No failed/partial positive receipt, original evidence file changes, or automatic Chrome retry.
- `POST /api/runs/:id/f3-q1-layout-acceptance` requires same-origin, strict JSON body exactly `{"confirm":"offline-anonymous-layout-review"}`, a **failed/interrupted `dynamic-passive` saved** eligible run and the shared Chrome-busy guard. HTTP 202 means running, never proof of completion. Studio adds an explicit opt-in button only when an eligible anonymous geometry preview is available.
- `GET /api/runs/:id/f3-q1-layout-acceptance` **never runs Chrome**. It rereads the receipt file and recomputes the expected current HTML/evidence SHA-256; 200 only if the full receipt fields and both view results match. 404 not started, 202 running, 409 conflicting/failed. Studio shows the stored receipt download only after verified 200. Authentication or digitally signed source authenticity is **not** inferred; a fully forged consistent local evidence set cannot be proven genuine by a self-contained hash.
- One-time prevention: existing on-disk receipt returns conflict on repeated POST and mode/activity guards prevent overlapping browser replay. A changed inspection/report means the saved receipt is invalid even if the old positive result exists.
