# Web REA Studio — Quality-first completion contract (2026-10-17)

Quality and verified independent outputs take precedence over feature count or speculative percent-complete estimates. This is a repeatable acceptance plan, not a calendar promise.

## Ultimate demonstration
On at least three varied, authorized **real** sites: URL → safe observation → source-attributed structure and behavior model → independently runnable replacement → measured Chrome comparison → bounded automatic correction → export. Unknown server/database functions must remain flagged unknown or explicitly simulated.

## Non-negotiable product acceptance gates
| Gate | Required proof | Automatic blocker |
| --- | --- | --- |
| Permissions | Exact authorized origin, approved methods/paths, action risk and budgets | Unknown host, unapproved action, credential leak |
| F1 | Real DOM affordances and observable states, explicit blind spots | Only a screenshot or assumed interactions |
| F2 | Per-action before/after state and network evidence | Temporal coincidence promoted to API causality |
| F3 | Evidence-linked spec, unsupported functionality explicitly unknown | Invented hidden backend/database behavior |
| F4 | Independent runnable application and deterministic state/data contract | Mock screenshot, iframe, original-server dependency |
| F5 visual | Full screenshot area, dimension/coverage, pixel/geometry comparison at controlled viewports | Cropping, untracked masking, missing or bad metrics |
| F5 repair | Demonstrated pre/post improvement with fresh independent Chrome reruns | Unmeasured code changes, regressions |
| Product | Multiple distinct real sites, downloadable build, security/QA report | Synthetic fixture success alone, unchecked Vercel mock |

## Ordered stages

### Q0. Eliminate false-positive visual comparisons — CI verified
- Compare the full captured canvas. No unconditional right-bottom ignored notice area.
- Missing/cropped image pixels count as maximum mismatch. Record full pixel grid, overlap, missing samples and coverage.
- Static-only quality gate: equal dimensions, complete sampled coverage, pixel match >=90%, RGB MAE <=20, geometry region match >=70%, no hidden mask.
- These are early CI regression thresholds, not calibrated universal fidelity requirements.
- A passing static visual gate explicitly does not certify behavior, API parity, autonomous repair or a production-ready product.
- Regression includes cropped-but-identical-overlap screenshot, missing geometry, disallowed mask and major color mismatch. Existing historical P5 measurements are not silently regraded.

### Q1. Resolve first real-site capture with authorization
- Retrieve already saved Windows failed-run support packet, inspect hostname/privacy locally, confirm cause and exact scope.
- If an external API is truly required, get specific explicit authorization before any new host, path, method, DNS/TLS pinned relay or CSP behavior change.
- Demonstrate real data-ready state, or label a safe approved synthetic substitute rather than pretending original data was recovered.

### Q2. Verified real-world F1/F2/F3
- Start with low-risk explicitly approved controls and bounded read-only paths.
- Record per-action before/after states, attribution to API when actually proven, coverage and unknowns.
- Generate evidence-led specs and privacy-safe artifacts.

### Q3. End-to-end independently runnable F4
- Generate independent UI, state machine and data contract for one real authorized site.
- For inaccessible backend/DB, use approved interfaces or clearly labeled local simulations.
- Validate user flows in independent Chrome without dependence on the target website.

### Q4. Closed-loop F5 repair
- Capture original and independent app across more than one viewport. Rank measurable mismatches.
- Apply bounded candidate changes, rerun Chrome, compare before/after geometry, pixel and function outcomes.
- Do not claim repair if no measured improvement. Stop and pivot after two failed attempts.

### Q5. Multi-site product hardening
- Repeat on at least three diverse authorized sites, including a fresh unseen target.
- Final output: runnable/source package, reproducibility instructions, regression and security evidence, known limitations, budget caps and safe rollback.
- Declare complete by reliable independently observed outcomes, not a self-selected percent.

## Active evidence boundaries
- Synthetic fixture/Chrome tests are regression proofs, not real-site equivalence.
- User Windows local outcomes, GitHub CI, approved real targets, preview and Production have separate verification states.
- Do not loosen real network policy, change Vercel, authorize unknown hosts, expose private evidence or alter unrelated repositories without owner approval.
- After every bounded work unit: code + tests + private GitHub commit + HANDOFF.md update + CI/HEAD verification.
